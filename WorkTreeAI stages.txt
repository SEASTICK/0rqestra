(Source of truth for Stage 1. Supersedes earlier Mac-only / Windows+Mac-only drafts discussed
in conversation — this is the corrected, final version: Windows PC and macOS are both full

PRODUCT

WorkTreeAI is a public, open-source desktop application for Windows PC and macOS, with an iOS
companion planned later.

Users open an existing local software project and manage a team of AI agents through an
editable visual tree.

The interface has:
- An agent tree on the left.
- Chat and live agent activity on the right.
- Node settings for role, provider, model, instructions, tools, and usage limits.

Users connect supported official provider CLI tools, initially OpenAI Codex CLI and Claude
Code CLI, through supported authentication methods. Provider documentation and subscription
conditions must be verified before implementation, not assumed.

The desktop app runs the provider CLIs and project commands locally. AI inference is handled
by the connected providers, not by WorkTreeAI itself.

AGENT BEHAVIOUR

The Manager is the user's only conversation partner.

For every prompt, the Manager:
- Interprets the request for routing.
- Delegates specialist planning and work to configured agents.
- Tracks task progress.
- Routes problems to appropriate specialists.
- Passes findings and results between agents.
- Reports outcomes and asks the user questions when necessary.

The Manager does not write code, perform specialist reviews, or solve technical problems
itself.

App-provided specialist roles include:
- Planner
- Builder
- Code Reviewer
- Debugger
- Tester
- Security Reviewer

Users can customize the tree, add multiple agents with the same role, and choose each agent's
model and instructions.

The Manager:
- Uses only configured agents.
- Follows permitted tree connections.
- Never silently creates agents or changes models.
- Runs work automatically within configured permissions.
- Asks the user when a role is missing, a decision requires input, or a retry limit is reached.
- Pauses affected tasks while independent work may continue.

Agent activity is visible, but all user-facing questions and final summaries come through the
Manager.

ALREADY DECIDED (not to be asked again)

  - Desktop stack: Electron + TypeScript + React (2026-11-16).
  - Clicking "+" beside a node adds a child agent with the chosen role, provider, and model,
    automatically connected from that node (2026-11-16).
  - Among eligible agents with the same role, the highest-priority idle agent is selected
    (2026-11-16).
  - A1, correction returns: review findings go back to the authoring agent for fixes without a
    drawn return edge (2026-11-16).
  - A2, missing verification: the Manager asks first; if the user finishes without checking,
    the work is reported as "Completed - unverified (user chose to skip verification)"
    (2026-11-16).
  - A3, adding an agent to a paused request: the user approves a change summary; the request
    continues on the updated tree once none of its tasks are running; finished results are
    kept and queued work is re-checked (2026-11-16).
  - A4, tree edits during a request: the running request keeps the tree it started with; edits
    apply to new requests only, or through the A3 approval (2026-11-16).
  - A5, limits: defaults of 25 launches per request (retries and corrections count), 2
    retries, 3 review rounds, 3 outage retries, 50 Manager turns; at the request limit,
    running work finishes and queued work pauses (2026-11-16).
  - A6, planning: when a Planner is connected, every building or debugging request goes to it
    first; with no Planner, the Manager asks once whether to add one or proceed (2026-11-16).
  - A7, same-role details (2026-11-16):
      - priority always wins, even when the prompt names another agent (differs from the
        earlier draft);
      - an agent added with "+" gets the next free (lowest) priority in its role;
      - when every eligible agent is busy, new work waits for the top-priority one, even if a
        lower-priority agent becomes free sooner (differs from the earlier draft).
  - A8, "+" picker: role, provider, and model start unselected; the agent can be added only
    when all three are chosen (2026-11-16).
